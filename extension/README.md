# 妙言剪藏（MiaoYan Clipper）

浏览网页时把**正文、选中文字、框选区域、页面截图**剪藏成妙言 Markdown，直接写进本地妙言笔记库；保存时可以选目标目录，图片自动落到分类下的 `i/` 目录。

> 妙言没有对外接口也没有插件系统，笔记就是库目录里的 Markdown 文件。本扩展用 Chrome 的文件系统访问 API 直写你的磁盘——没有常驻进程，笔记始终在你自己的机器上。

## 安装（本地加载）

1. 打开 `chrome://extensions` → 开启「开发者模式」
2. 「加载已解压的扩展程序」→ 选择本目录（`miaoyan-clipper/`）
3. 点扩展图标 → 齿轮「设置」→ 「选择目录」，授权**妙言笔记库根目录**
   （默认位置：`~/Library/Mobile Documents/iCloud~com~tw93~miaoyan/Documents`）
4. 要求 Chrome 116+；目录只需授权一次，长期有效

## 用法

**三种发起方式**（随手用哪个都行）

- **点地址栏旁的扩展图标** → 直接剪当前页：先摆出正文范围框，确认后弹出卡片保存。
- **快捷键**：⌘/Ctrl + `Shift+S` 整篇正文、`Shift+K` 框选、`Shift+P` 截图剪藏
  （可在 `chrome://extensions/shortcuts` 改成你顺手的键）
- **网页右键菜单**：整篇正文 / 剪藏选中文字 / 框选剪藏 / 截图剪藏

**网页右键菜单**

- 框选剪藏：页面空白处拖拽画框 → 自动定位正文块 → 转 Markdown
- 剪藏选中文字：先划选再右键
- 整篇正文：先按识别结果在页面上摆出**范围框**，确认后才剪 —— 见下面「全文剪藏的范围框」
- 截图剪藏：抓当前可见页面 → 再拖框裁剪 → 存成图片笔记

**侧边栏**（用 Chrome 的侧边栏按钮打开，不是点扩展图标）

- 编辑 / 预览双 tab，可改标题、加标签
- 目标目录：下拉选分类，或点「新建」直接建分类
- 「保存到妙言」写盘
- 空状态里有「剪藏当前页面」按钮；面板里的草稿不是当前页时，会显示「这是上一次剪藏的内容」并给出「剪藏当前页面」

**保存之后**

- 浮层自动收起，底部留一条提示：保存到了哪个目录哪个文件，附带「继续剪藏」按钮（连着剪下一篇）
- 剪藏过的页面，标签页上会打一个 ✓
- 标签会被记住，下次剪藏自动填好

### 全文剪藏的范围框

「整篇正文」不会直接开剪，而是先框出识别到的文章主体：

- 深色遮罩外面是**不会剪**的部分，框内才是要剪的内容
- 拖动 8 个手柄（四角 + 四边）可以缩小 / 放大范围；按住框顶的说明条可以整体移动
- 说明条实时显示「将剪藏 什么 · 约多少字」，拖完会变成「N 个内容块 · 约 M 字」
- `Enter` 或点「✓ 剪藏这块」确认；`Esc` 或「取消」放弃；「重新识别」重跑一次自动识别
- 确认后只剪**框内**的块级内容（段落 / 标题 / 列表 / 表格 / 图 / 代码块），框外的最后一段、相关阅读都不会带进来

自动识别本身也会先滤掉一批噪声：`class/id` 命中广告/推荐/热榜关键词的块（且相对正文够小），
以及「相关阅读 / 猜你喜欢 / 热门排行 / 版权声明 / 关注我们」这类标题下的整块内容。

#### 默认框落在哪：按段落给正文打分（v0.3.1）

默认框不是「页面上字最多的块」，而是按**段落**给容器打分选出来的：

- 页面里每个 `<p>` / `<pre>` / `<blockquote>` / `<td>` / `<dd>` 按「长度 + 标点密度 − 链接密度」算权重，
  权重全量记给它的父容器、半量记给祖父容器 —— 所以**不需要 class 名带 article/content 也能找到正文层**
- 容器再乘一组修正：链接密度（导航/目录重罚）、`ad/recommend/sidebar/comment` 类名重罚、
  `article/body/content/post` 类名加成、`<article>`/`<main>` 标签加成、`<body>` 折价
- **主标题锚点**：包含页面主标题（与 `document.title` / `og:title` 对得上的那个 `h1`）的容器 ×1.8，
  评论区和推荐位通常不包含标题，这一条能把「评论区比正文还长」的站点掰回正文
- 正文容器不含标题、而旁边正好是标题块（`<h1>` 或 `<header><h1>`）时，范围自动上探一层把标题带上

在 5 个测试页上的实测选择（v0.3.0 → v0.3.1）：

| 页面 | v0.3.0 | v0.3.1 |
| --- | --- | --- |
| 常规文章（`article.post-content`） | `article.post-content` | 不变 |
| 正文里混广告/推荐栏 | `article.post-content` | 不变 |
| 类名全是乱码 `a9/b7/c3/d5` | **`body`（整页）** | `div.a9`（正文列 640×459） |
| 评论区比正文长（`.discuss` 540 字 vs 正文 425 字） | 正文容器 | 不变 |
| 侧栏是全链接热门列表 | `main.reading` | 不变 |

**设置页**（齿轮）

- 库目录授权 / 清除授权
- 默认目标目录
- 图片处理：下载到 `i/`（默认，离线可用）或保留远程链接
- frontmatter 内容开关：来源链接 / 站点·作者·剪藏时间 / 标签
- 剪藏后自动开侧栏、图片失败退回远程链接
- 「目录与权限诊断」：对比「设置页上下文」与「后台 Service Worker 上下文」读到的目录数、权限状态与报错；
  授权后如果页面浮层里没有分类目录，先点「刷新目录列表」，再点「运行诊断」把结果发出来即可定位

## 目录授权：只在真正写不动时才要你确认（v0.3.2）

v0.3.2 之前，扩展会**先查一遍权限、查不到就直接报「授权过期」**，于是每次保存都像在要授权。
现在的顺序反过来了——**先写，写不动再申请授权**：

1. 点保存 → 直接在妙言库目录里写文件
2. 只有文件系统真的抛 `NotAllowedError` 时才申请权限；这时如果你正点在侧栏的保存按钮上，Chrome 会弹一次确认框
3. 授权一次后 Chrome 会长期记住；浏览器重启 / iCloud 重新挂载导致权限退回时，只需在侧栏点一次「**确认授权并保存**」，草稿会自动接着存

如果保存是从页内浮层触发的（没有用户手势，Chrome 不会弹框），侧栏会自动打开，
授权卡的按钮会变成「**确认授权并保存**」——点一次就好，不用重新选目录。

## 会带出最近用过的目录（v0.3.2）

保存成功后扩展会记住这次用的分类（`settings.lastFolder`）：

- 侧栏「目标目录」默认选中它
- 页内浮层的「目标目录」也默认选中它
- 设置页里的「默认目标目录」只在还没用过时生效（`lastFolder` 为空时）

## 提示「目录授权过期 / 权限已失效」怎么办

浏览器重启、扩展重载、或者 iCloud 目录重新挂载后，Chrome 会把已经授权过的目录退回「待确认」状态：
句柄还在（目录名还在），但 `queryPermission()` 不再返回 `granted`。这时**不需要重新找目录**：

- 侧栏顶部的授权卡会出现「**重新授权此目录（推荐）**」按钮 → 点一下，Chrome 弹确认框 → 选「允许」
- 设置页「妙言笔记库」一行也有同样的按钮
- 如果是点了按钮仍然失败（例如权限被明确拒绝），再用「选择妙言库目录 / 选择目录」重新选一次

授权成功后，之前因为权限失效没存成功的草稿会自动续存。

## 目录读不到子目录时怎么办（iCloud 目录常见）

妙言库在 iCloud Drive（`~/Library/Mobile Documents/...`）下，属于系统的 File Provider 目录。
Chrome 的文件系统访问 API 在**后台 Service Worker 上下文**里有时读不到这类目录的句柄或子目录，
但**扩展页上下文（侧栏 / 设置页）**里是正常的——所以本扩展把「枚举目录」和「写盘」都放在扩展页里做：

- 侧栏 / 设置页枚举成功后，把目录树写进 `chrome.storage.local`（`folderTree`）
- 页内浮层读不到扩展的 IndexedDB，直接读这份缓存，所以浮层里的「目标目录」是完整分类列表
- 后台写盘失败（权限失效 / 读不到句柄）时，把保存请求转交侧栏代存，浮层会提示并自动轮询结果

若某次仍然只看到「（库根目录）」：设置页点「刷新目录列表」→「运行诊断」，把报告发回来即可。

## 写出的笔记长什么样

```markdown
---
title: "文章标题"
来源: "https://example.com/post"
站点: "example.com"
作者: "某某"
剪藏时间: "2026-11-22 21:48"
标签: "剪藏, 技术"
---

正文……

![示意图](/i/img-1a2b3c.png)
```

- 文件名取自标题，禁用字符 `/ : * ? " \ | < >` 自动换成全角，同名自动加 ` (2)` 序号
- 图片存放在**笔记所在目录的 `i/` 子目录**，正文用 `/i/<文件名>` 引用
- frontmatter 全是标量 `key: value`，妙言会正确隐藏这一块

## v0.6.0 改了什么（权限最小化：不点剪藏，就看不到任何网页）

| 改动 | 你能感觉到什么 |
| --- | --- |
| 安装时**不再申请任何网站访问权** | 装完不弹「读取所有网站数据」这种吓人提示；`manifest.json` 里没有 `host_permissions`，也没有 `content_scripts` |
| 剪藏改成**按需注入** | 只有你点图标 / 右键 / 快捷键那一刻，Chrome 临时把当前页交给扩展，随后才注入剪藏脚本 |
| 跨站图片按站点授权 | 第一次把某 CDN 的图存到本地时会问一次；拒绝也行，图片保留原始链接，笔记照常保存 |
| 设置页新增「网站访问权限」 | 看得到保留了哪些站点，可一键全部撤销 |
| 保存结果写明图片情况 | 「N 张图片未下载到本地，已保留原始链接」，不再静默丢图 |

> 为什么改：商店里「宽泛主机权限」是拒审高发区，一句「需要访问所有网站」就要写长篇理由。
> 现在安装包只申请 `activeTab` + `scripting` + `tabs` + `storage` + `contextMenus` + `sidePanel`，
> 主机权限是**可选**的（`optional_host_permissions`），用户用到才给。
>
> 代价（诚实说明）：跨站图片第一次要确认一次；如果你想全部站点都免问，
> 可以在 `chrome://extensions` 的「详细信息 → 网站访问权限」里把它改成「在所有网站上」。

## v0.5.0 改了什么（交互：像印象笔记那样一点就剪）

| 改动 | 你能感觉到什么 |
| --- | --- |
| **点地址栏旁的扩展图标 = 直接剪当前页** | 不用再右键翻菜单；点一下就出范围框 |
| 快捷键 ⌘/Ctrl + `Shift+S` / `Shift+K` / `Shift+P` | 整篇 / 框选 / 截图，一按就发起 |
| **保存成功后浮层自动收起** + 底部提示条 | 不会挡住页面；提示条里能直接「继续剪藏」下一篇 |
| 标签会被记住 | 下次剪藏标签已经填好 |
| 剪藏过的页面标签打 ✓ | 一眼看出哪些页面已经存过 |
| 侧边栏空状态 / 旧草稿提示条都有「剪藏当前页面」 | 上一篇的内容不会误当成这一篇 |

> 所以框选改用 `⌘+Shift+K`、截图用 `⌘+Shift+P`。
> `test/probe-shortcuts.mjs` 就是干这事的探针，改键位前先跑它。

## v0.4.0 修了什么（安全与数据完整性加固）

这一轮是按一次完整审计的结果修的，重点是**别弄坏你的笔记**和**别让网页偷看你的库**。

| 改动 | 你能感觉到什么 |
| --- | --- |
| `pendingSave` 消费即删 + 去重 | 不会再「每开一次侧栏就多出一篇 `标题 (2).md`」 |
| 图片占位符改用完整序号正则 | 一次剪十几张图也不会丢图、不错位 |
| 保存同名笔记加锁（Web Locks） | 连续剪藏时同名笔记不会被后一次覆盖 |
| 文件名比较按大小写/Unicode 归一化 | macOS 大小写不敏感的盘上不会覆盖你已有的笔记 |
| 浮层改成 closed shadow + 随机宿主 id | 网页脚本读不到你的目录结构，也没法替你点保存 |
| 隐藏内容（`.d-none`、未展开的 `<details>`）不再被剪进笔记 | 笔记更干净 |
| 图片下载加超时/上限，**默认拒绝内网地址** | 不会被网页拿来探测你局域网（需要时在设置页打开开关） |
| 来源地址里的 token/签名自动脱敏 | 笔记里不会长期留着一枚能用的凭据 |
| 截图统一转 JPEG 并限长边 | 截图剪藏不会再因为会话存储超限而丢内容 |
| 撤销授权时清掉缓存的目录列表 | 撤销后本地不留你的目录名 |
| 删掉没用到的 `scripting` 权限 | 商店审核少一条要解释的权限 |
| `file://` / `chrome://` 页面右键剪藏会提示不支持 | 不再点了没反应 |

隐私政策见 `PRIVACY.md`（商店上架时用同一份）。

### 截图剪藏需要先点一次扩展图标

浏览器只在「用户主动触发」时才允许截取当前页（`activeTab` 授权）。
所以第一次用截图剪藏，请**先点一下工具栏里的扩展图标**（或用右键菜单「妙言剪藏 → 截图剪藏」），
否则会提示「截图失败，可能需要先点击一次扩展图标」。

## 已知限制

- 目录授权必须手动点一次（原生目录选择器无法自动化）
- iCloud 目录在后台上下文里可能读不到子目录，已改为扩展页上下文枚举 + 缓存同步；若仍异常用设置页的「运行诊断」定位
- 截图剪藏只截当前可见区域
- 整篇正文靠启发式打分识别（段落权重 + 类名语义 + 主标题锚点），抓偏了可以拖范围框修正，或用框选兜底
- 识别质量只在 5 个自建测试页上验证过，没在真实站点逐一手测；纯图片站、纯表格站、单页应用虚拟滚动列表可能仍会偏
- 范围框只认 DOM 里已有的块：无限滚动/虚拟列表里还没渲染的内容、跨域 iframe 里的正文，框住也剪不到
- 自适应布局下换行会变，拖动后的「框内命中」按当时 layout 算（预期行为，但没在真实站点逐一手测）
- 需要登录或有 Referer 校验的图片可能下载失败，可设置退回远程链接
- v0.6.0 起安装时不申请主机权限，剪藏依赖用户手势（点图标 / 右键 / 快捷键）授予的 `activeTab`；没有任何手势时，扩展看不到任何网页
- 跨站图片要按站点授权一次；不授权就保留原始链接（想省事可在 `chrome://extensions` 把网站访问权限改成「在所有网站上」）
- 仅支持 Chrome 116+；v0.6.0 已上架 Chrome 应用商店 → <https://chromewebstore.google.com/detail/妙言剪藏/pbdpebhchbkgmgdgdehnoppglilakiaj>
- 截图剪藏依赖浏览器授予的 `activeTab`，自动化测试跑不了这条手势路径，需人工点一次扩展图标验证
- 快捷键最多 3 组（Chrome 限制每扩展 4 个建议键），且 macOS 上部分字母键被浏览器占用，改键位前先跑 `test/probe-shortcuts.mjs`
